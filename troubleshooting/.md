
# Windows Infrastructure Troubleshooting



This document records common troubleshooting procedures performed during the Windows infrastructure lab.

---

## 1. Check Hostname

```cmd
hostname
```

Used to verify the computer/server name.

Expected examples:

```text
DC01
CLIENT01
```

---

## 2. Check Current User

```cmd
whoami
```

Used to verify the currently logged-in account.

Example:

```text
corp\john.it
```

---

## 3. Check IP Configuration

```cmd
ipconfig /all
```

Used to verify:

* IPv4 address
* Subnet mask
* Default gateway
* DNS server

For CLIENT01, the DNS server should point to the private IP address of DC01.

---

## 4. Test Network Connectivity

```cmd
ping DC01
```

Used to verify connectivity between CLIENT01 and the Domain Controller.

---

## 5. Test DNS Resolution

```cmd
nslookup corp.local
```

```cmd
nslookup dc01.corp.local
```

Used to verify that the Active Directory domain and Domain Controller can be resolved through DNS.

---

## 6. Verify Domain Information

```cmd
systeminfo | findstr /B /C:"Domain"
```

Used to verify that the computer is connected to the expected domain.

Expected:

```text
Domain: corp.local
```

---

## 7. Troubleshoot Group Policy

Force Group Policy update:

```cmd
gpupdate /force
```

Verify applied policies:

```cmd
gpresult /r
```

Check whether:

```text
Corporate-Security-Policy
```

is listed as an applied policy.

---

## 8. RDP Troubleshooting

If RDP to DC01 or CLIENT01 fails, check:

1. EC2 instance is running.
2. Correct public IP is being used.
3. Security Group allows TCP `3389`.
4. Security Group source is the current **My IP**.
5. Windows Remote Desktop is enabled.
6. The administrator's public IP has not changed.

The RDP rule should **not** use:

```text
0.0.0.0/0
```

---

## 9. Domain Join Troubleshooting

If CLIENT01 cannot join `corp.local`, verify:

```text
CLIENT01 DNS → DC01 private IP
```

Then test:

```cmd
ping DC01
```

```cmd
nslookup corp.local
```

If DNS resolution fails, correct the CLIENT01 DNS configuration before attempting the domain join again.

---

## 10. File Share Troubleshooting

If a user cannot access a department share, verify:

* User account
* Security group membership
* NTFS permissions
* Share permissions
* DNS resolution
* Network connectivity

Example:

```text
\\DC01\HR
\\DC01\Finance
\\DC01\Sales
```

---

## 11. Windows Services

PowerShell can be used to check services:

```powershell
Get-Service
```

Important services for this project include:

```text
DNS
NTDS
Netlogon
LanmanServer
TermService
```

---

## 12. Process Troubleshooting

To view running processes:

```powershell
Get-Process
```

This can help identify applications or processes consuming system resources.
